# Публикация демо

Репозиторий: `maxkosyakoff/workshop`, ветка: `test`.

## Автоматическая публикация

Workflow `.github/workflows/demo.yml` запускается при push в `test`, проверяет правила игры, собирает только браузерные файлы в `dist/` и загружает их в GitHub Pages. Дизайн-документы, локальный сервер и тесты в сайт не попадают.

Однократная настройка владельцем репозитория:

1. Открыть <https://github.com/maxkosyakoff/workshop/settings/pages>.
2. В Build and deployment выбрать Source → GitHub Actions.
3. Если environment `github-pages` ограничивает ветки, разрешить публикацию из `test`.
4. Открыть Actions → Publish PC demo → последний запуск → Re-run failed jobs, если первый запуск ещё до включения Pages завершился ошибкой. Следующие push в `test` публикуются автоматически.

Ожидаемый адрес после успешного развёртывания: <https://maxkosyakoff.github.io/workshop/>. Адрес не означает, что развёртывание уже завершилось; источник истины — успешный deploy в Actions и фактическая загрузка сайта.

GitHub Pages для приватного личного репозитория требует подходящего платного плана, например GitHub Pro. Если настройки предлагают Upgrade, текущего плана недостаточно. Публикация в таком случае требует отдельного решения владельца: другой хостинг, смена видимости репозитория или тариф. Эти настройки автоматически не меняются.

Официальная документация: <https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages>.

## Локальная сборка

```powershell
node --test prototype/tests/game.test.mjs
node prototype/scripts/build-demo.mjs
```

Содержимое `dist/` можно разместить на любом статическом HTTPS-хостинге. Все пути относительные: сайт работает в подкаталоге `/workshop/`. Сервер Node.js нужен только для локального запуска, но не для размещённого демо.

Сохранение привязано к браузеру и домену. Прогресс с localhost не переносится на опубликованный сайт.
